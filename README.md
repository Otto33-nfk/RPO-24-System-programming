# Лабораторная работа: многопоточность и асинхронность в Go

## Запуск

```bash
go run .
```

## Проверка тестов

```bash
go test -timeout 15s ./...
go test -race -timeout 30s ./...
```

## Файлы проекта

- `main.go` - запуск заданий, замеры времени и вывод результатов.
- `worker.go` - обработка одного задания, последовательный запуск и пул горутин.
- `worker_test.go` - тесты.
- `go.mod` - модуль Go.

## Что делает программа

Программа обрабатывает числа от 1 до 8. Для каждого числа она ждёт 200 мс и вычисляет квадрат.

Сначала задания выполняются последовательно. Затем программа запускает пул из одного и четырёх обработчиков. Каждый вариант запускается три раза, а в итог выводится медианное время.

В конце программа запускает пул из четырёх обработчиков с таймаутом 300 мс. При таймауте выводятся результаты, которые успели завершиться, и ошибка `context.DeadlineExceeded`.

## Замеры

Фактические значения времени выводятся при запуске `go run .`. Они могут немного отличаться на разных компьютерах. Для сравнения используется медиана трёх запусков.


| Режим | Медианное время в этом запуске | Результат |
| --- | ---: | --- |
| Последовательно | 1,603 с | 8 результатов, сумма 204 |
| Пул из 1 обработчика | 1,603 с | 8 результатов, сумма 204 |
| Пул из 4 обработчиков | 0,400 с | 8 результатов, сумма 204 |
| Пул из 4 обработчиков, таймаут 300 мс | около 0,3 с | 4 результата, ошибка таймаута |

Ускорение относительно последовательной обработки:

- Пул из 1 обработчика: **1,00 раза**.
- Пул из 4 обработчиков: **4,00 раза**.

## Краткие ответы на контрольные вопросы

1. **Чем горутина отличается от потока операционной системы?** Горутина - это более лёгкая единица выполнения, которой управляет Go. Поток создаётся и управляется операционной системой. На одном потоке может выполняться несколько горутин.
2. **Может ли пул ускорить ожидание на одном ядре? Почему?** Да. Пока одна горутина ждёт таймер или внешний ресурс, другая может выполнять работу. Для такой задачи не обязательно иметь несколько ядер.
3. **Почему канал результатов закрывается после завершения обработчиков?** Потому что обработчики отправляют в него результаты. Если закрыть канал раньше, отправка завершится паникой. После `Wait` все обработчики закончили отправку.
4. **Что произойдёт, если обработчик отправляет результат, а получатель уже завершился?** Если отправка не может выполниться, обработчик может зависнуть. В этой программе отправка результата также ожидает `ctx.Done()`, поэтому при отмене контекста обработчик может завершиться.

Команды выполнены успешно:


## Кто закрывает каналы

- Канал `jobs` закрывает горутина, которая отправляет задания.
- Канал `results` закрывает отдельная горутина после `wg.Wait()`, когда все обработчики завершились.
